## 可供裁定的路线

### A：新增一台 API 同钟首败取证，推荐

**补的缺口。** 先检验“首次身份请求是否连最早可见故障的时间前提都不满足”。当前原 core 已不可用，无法从本地再次解析补齐这条边界。A 不重复绿色矩阵，也不承诺一次就区分产品、Node 和 TCG。

**前置材料。** 复用上述 CI562 企业候选、manifest、六份原助手、准确公开二进制和原工具闭包。未来开工先核同次新账本及输入；原件不可得、摘要不符或容量不足即不启动，不重新下载替代候选或换版本。未来只验证诊断包装的同钟记录、隐私投影和停止控制，不在本轮编写或执行这些夹具。

**拟议操作。** 只在外部取证包装及既有受限 handler 中增加以下有界记录，不改产品镜像、HTTP body／headers、请求顺序或业务保证：

1. 在同一 guest 的同一 boot ID 下，记录 handler 启动的 `CLOCK_MONOTONIC`，并在读取 core 或启动 GDB **之前** 写 owner／captureId 绑定的安全首败标记。仅登记准确原 API Node；PID 变化不重新登记。
2. 客户端沿原调用记录调用意图和返回边界；原测试反向代理只增加固定 `auth-install` 路由枚举、唯一请求序号及接收／转发／响应边界的 guest monotonic。不得记录 URL 参数、header 值、body、响应内容或真实凭据。代理“开始转发”只证明转发意图，不能冒称 API 路由已执行。
3. 监督包装以至多每秒一次的频率核准确首败标记，首败后停止驱动后续动作，并记录已有前缀子进程的取消／退出边界。到原请求位置时若已见该 Node 的首败标记，就不发送目标请求。若命令或请求已在途，不能宣称已召回；保留原结果／取消结果，不重试。仅为完成原有界安全采集保留故障进程所需上下文，不启动更多业务命令；不得为了等待观察登记、首败标记或更多日志而延迟原请求。

**拟议预算。** 新增且仅新增一台，不续用旧许可：外层 4 CPU／6 GiB、memory+swap 总上限 6 GiB；guest 原 4 vCPU／4 GiB／40 GiB，原 TCG、QEMU／Node／内核／磁盘及网卡保持。全窗最多 9000 秒，原安装 1800 秒、健康 180 秒、首次身份客户端 90 秒、产品业务 30 秒分别保持。原匿名 core 512 MiB、handler 90 秒、GDB 最多 60 秒保持。新安全回执每条至多 4 KiB、全窗至多 32 条，超限即记诊断失败并停，不滚动覆盖首败。

**数据边界。** 原 core 继续只在无 swap guest 的匿名 RAM 内处理，finally 关闭，不增加持久 core、guest 磁盘或原始 GDB 输出导出。只新增同钟时间、固定阶段、序号、准确归属和结果分类。无新设备、宿主挂载、端口、权限、凭据或内网接入；不改 ACL、YAMA 或其他项目配置。安全投影失败即停，不导出私有数据补救。

**成功、失败及停止。** 成功只指同一 boot／Node／captureId 的时间边界和安全首败证据齐全。若 handler 已在客户端调用意图之前启动，便足以反驳“这个尚未发起的请求触发最早故障”；代理尚未转发时同样不能称 API 已处理该请求。反过来，handler 晚于代理接收／转发只说明顺序相容，不能证明请求致因，因为 signal 到 handler 仍有调度延迟。无故障、缺同钟记录、迟注册、输出超限或工具超时均是有限或不完整样本，不关 P1。首败、目标完成、任一原期限或 9000 秒先到即停；无第二台、MCP 窗口或自动后续对照。

### B：新增一台 API 在线 GDB 取证，暂不推荐

**补的缺口。** 尝试在准确 API Node 首次 SIGSEGV 停止点直接取得受限 native 栈，避开本次 GDB 在 core-file 阶段超时造成的信息缺口。它需要新的调试方式和期限裁定，不能冒称原 60 秒 GDB 方案的离线续跑。

**已有基础与限制。** 原源码已有 `NativeDebugger`，可作为实现参考；本轮只读了源码，没有运行它。它现有的附加等待、全线程 bt 和输出收集不能直接照搬为本方案。未来必须先完成准确角色／PID 核准、总期限和输出上限的包装验证。不能预认原 guest 的 ptrace 一定可用；拒绝即停，不增权或改系统设置。

**拟议操作及新增边界。** 在原 API 启动时并行附加同一准确 Node，不等待附加来延迟原请求。取得首个 SIGSEGV 时，只读故障线程至多 12 帧，关闭参数、locals、自动脚本、网络符号下载和共享库自动加载。只投影至多 40 个既有允许前缀的公开 native 符号、阶段和摘要；不采 JS／JIT 私有数据或任意内存，不输出寄存器值。既有匿名 core handler 可保留安全 ELF 投影，但取消其后置 GDB 子步骤，避免两次 GDB 或自动回退。

B 新申请的 GDB 从附加开始到等待信号、取栈、detach／退出合计 **最多 900 秒**，包含等待，替代原后置最多 60 秒；其中首信号后的取栈／detach 最多 60 秒，另有的 handler 仍最多 90 秒。不得把 900 秒说成原授权。原 9000 秒全窗及 A 列出的 guest／外层、原候选、设备和全部产品期限均不增加。GDB stdout／stderr 合计最多 64 KiB，只在本机内存中筛选后保留安全投影及摘要，达到上限立即停止调试；不上传或提交原文、core 或秘密。

**成功、失败及停止。** 成功只指首个 signal 在准确已登记进程内停止、有限 native 栈完成并安全 detach；若仍止于公开 Node 范围、没有因果链，则仍不支持产品修复。已有更早首败、附加被拒／迟到、900 秒先到、取栈 60 秒先到、输出上限、目标完成或原全窗到期即停止，安全 detach／结束调试并收尾；不再运行后置 GDB，不等第二次崩溃、不重新登记重启 PID。预算内不能 detach 就按该样本失败停止 VM，不改策略重试。在线调试会暂停目标并可能改变请求结果，必须明确记为诊断干预，不能把其 HTTP 结果代普通产品验收或证明原调用致因。
