## 少量可证伪解释

| 解释 | 本次需要的新证据 | 支持、反驳与局限 |
| --- | --- | --- |
| 产品生命周期或输入组合触发错误 | 同一原调用／进程身份、最早错误阶段、准确崩溃模块和公开帧 | 若定位到违反源码不变量的具体操作，固定运行时下旧输入失败、最小产品修正后同输入恢复，才支持产品修复；仅看到 Node／V8 帧不支持改某个业务函数 |
| Node 或其他运行依赖缺陷 | 精确程序、动态依赖摘要，实际故障位置与对应版本源码 | 需具体缺陷机制、受影响版本及与本次输入的因果证据。版本／帧相似不够；任何运行时变更另行裁定 |
| TCG 执行异常 | 精确 QEMU／guest、崩溃阶段，以及可核的架构状态或模拟器错误证据 | 单次只在 TCG 失败、原生未复现仍不够。若本次只得到公共 IC 帧，TCG 和产品／依赖仍无法区分；不自动追加原生／KVM／其他 QEMU 对照 |
| 捕获干预导致或改变观察 | 原业务时序、准备完成边界、采集次数及捕获本身耗时 | 捕获准备在原请求后完成即不能声称覆盖；后置采集不能解释此前的原普通 139。原请求失败与捕获失败分别记录 |

两个窗口目前均无本次故障 core。首先补齐“哪个准确进程在原窗口崩溃、落在哪个受信模块”的缺口，优先 A。**本方案不承诺一次运行足以区分三类原因。** 不能区分就保留未知并停回关口，不把更多诊断字段当根因结论。

## 每个窗口的最小执行边界

建议本次只批准 A 或 B 中的一个；另一窗口不随之获批。每个选项均为一次、最多一台干净 amd64 guest，总窗最多 9000 秒，包含准备、原前缀、原目标请求、捕获和收尾；没有第二次尝试。它不是续用 1200／1800 秒组件例外。

固定原 Node v22.19.0、QEMU `8.2.2+ds-0ubuntu1.18`、guest SHA-256 `6a81c37564db9b1ee84e141922625e1d7c5b389b99bb3c572e0243607d5bb4d2`、原 kernel、4 vCPU／4 GiB、磁盘／网卡／镜像／部署布局。保原安装 1800 秒、健康 180 秒、业务 30 秒及每项工具原期限。不改 Node 标志、容器重启策略、连接池、内存、鉴权、实时资格或事件／通知／事务保证。

### A：企业 API 首次业务调用

1. 从 CI562 精确源码与候选重建原 enterprise 前缀，止于序号 8 install 后的**一次原始 auth/install 调用**。不执行后续 business journey、MCP、升级、恢复或其他画像。
2. 只对安装 UUID／根哈希核准的企业 API Node 注册观察。在原 install 启动程序时并行识别唯一 Node PID／starttime／可执行文件身份，不能为了等待注册延迟原请求。没有按时注册就记缺口，原请求仍只执行一次。
3. 正常返回也立即停止该窗口；只报告该样本，不自动继续 B。更早失败则保存首败并停，不跳过前缀失败去发送目标请求。

### B：团队回退后 MCP initialize

1. 从 CI566 精确源码与候选执行原 team 前缀到序号 18 commit，保留前序安装、同程序升级和兼容回退。原记录与本次前缀逐项映射；任何偏离均停，不把新候选或新编号代入旧窗口。
2. 在该原 commit 期间并行核准唯一 MCP Node。保留原验证的一次 initialize，只有它成功时才发送原有的一次 get_work_item；不新增或重试请求。原 commit 完成或首次失败即结束，不执行后续恢复链或其他画像。这样保留安装器代码和原调用顺序，不靠修改旧候选来截断请求。前序原请求不变，不能把前缀改成只启动 MCP 的稀疏组件。
3. 既有 `prepare_native_watcher`／捕获逻辑须按 MCP 角色使用。若需要适配 A 的 API 角色，先做纯解析／身份选择测试；不改变应用命令、entrypoint 或原业务等待。

## 采集和停止条件

复用现有匿名 RAM 捕获：只处理已登记准确 Node 身份；core 上限 512 MiB、无 swap、handler 最多 90 秒、GDB 最多 60 秒。准备只读身份轮询最多每秒一次、最多 90 次；不在请求前读取完整可执行文件。仅保存阶段、时钟来源、关联摘要、退出事件和有界公开运行时帧。

保持现有 `core_metadata.py` 的隐私边界，不输出寄存器、堆／对象内容、原始地址、映射路径、参数、私有栈或原始 core。若核心位置不在受信 Node 模块，先记 other-or-unmapped，不能猜另一模块身份。需扩展模块解析时只限已核公开二进制及摘要，新增采集范围先裁定，不临时放宽过滤。

完整输入身份需同时保镜像闭包和运行中的 Node 身份；有完整镜像差异仍不能证明故障不适用最终环境。只有定位到实际致因差异，并以旧失败／最终输入修复证明其不再适用，才可提出闭合。最终正式验收继续使用已批准的完整 guest，不通过改口排除 TCG 来取绿。

GDB／固件等工具必须来自已有准确工具闭包。缺工具、版本或摘要不符，直接保存缺口，不安装新宿主依赖、申请设备或换版本。捕获受拒、超限、迟注册、首败或目标请求完成都触发停止；更早的业务失败优先保全。自然重启后的新 PID 不自动重新注册，不重试请求。

先将安全阶段落盘再后置解析。VM 到 9000 秒就终止本窗口，QEMU 0 伴宿主 TERM 不记正常成功。无最终回执时实际目标请求数记未知；捕获失败不补“无崩溃”。若只取得相似公共帧或有限阴性，仍不关闭 P1，也不自动扩大内存、期限、捕获范围或开启下一台。

写入独有资源账本，仅收尾归属已证且无活动引用的本任务 guest／容器／临时文件。共享 store／镜像、旧树、原远端、用户数据、未知卷和政策拒目标保持。全程不对外发布、外发故障日志、增权或接入生产。
