## 上下文与假设

补齐 Session、Plan/context、Approval、Lease、Recovery 的具名适配，完成正常执行和停止两条链。复用现有 `agentMutate`、`publishPlan`、`finishSessionInTransaction`、`stopAck`、`leaseAction` 和 `recoveryAuthorizationPredicate`，保留服务器状态、授权、批准及幂等门禁。

采用最小数据库增量保存原动作来源及等待条件，复用现有事件类型。按用户裁定，Pi 等待时结算公开回复，条件满足后自动生成唯一后续 Turn，重新准入。Human 控制与批准决定保留；Web UI、F/TA 新域、外发和发布不在范围内。

## 受控方案与安全合同

- **`docs/plan/agent-mcp-m1/`**：同步 README、spec/steering、savedplan/implementation、安全合同、compatibility、operation-decisions、lifecycle、verification 与来源/全文绑定，完整纳入本次两项阻塞修正和用户等待裁定。保存上一候选及原静态回执的历史含义；新计划两份原文一致，再核精确 main 全文。逐操作列 REST/Zod、SDK、MCP、Runner、policy/feature、凭据、角色、状态、scope、参数、输出、兼容策略和九类 DoD。区分 Git blob、工作树、平台注入全文与工具截断，缺失版本元数据记 `null`，保留 M0 历史缺口。
- **`docs/adr/0081-pi-execution-wait-continuation.md`**：新增 Proposed ADR，固定等待结算、持久条件、自动续 Turn 的授权与去重合同、Runner opt-in 和失败恢复；与更新后的来源确认 ADR 一起重新独审，文档同步及 blocking/high 闭合前不进入产品实施。
- **`docs/adr/0080-exact-session-execution-result-confirmation.md`**：提出新增 `GET /api/v1/agent-sessions/{id}/execution-result`，`operationId=getAgentSessionExecutionResult`；查询必须携带 `action=complete|stop_ack` 和原 `operationKey`。返回准确 Session 状态/revision、原动作确认状态、原结果引用及清理概要；原结果绑定其提交时 revision，不以当前 Session 状态冒充该动作成功。回执缺失或保留期届满明确不可确认，错动作或错 Session 不返回他人结果。
- **身份合同**：采用专用 `human_or_installation_target` policy。C/安装凭据无写入解析，Human 保留原合法读取，普通 E 拒绝。重验 credential、Connection、Agent、principal、Team grant、Delegation 和精确 scope；Agent 确认必须匹配原 complete/stopAck 回执同事务保存的来源快照。快照由实际请求的 `actor.credentialHash` 定位准确 E Token，再绑定其 installation ID 与唯一 Connection；同 Connection 轮换允许，原生安装必须匹配原 installation ID。任意历史 Token 关联不构成证明；旧回执或来源缺失、歧义对 Agent 失败关闭，不能推测回填。查询不调用 `resolveCoordinationIdentity`，不更新使用时间、签 Token、续 Session、写 receipt/event/outbox；拒绝审计沿既有独立账本。
- **方案门禁**：先提交上述受控文件及 ADR 提案，交平台另一 Agent 独审；blocking/high 闭合、Chief confirm 后才执行以下产品变更。不以内部检查代替独审。
