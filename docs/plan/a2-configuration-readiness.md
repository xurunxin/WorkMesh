## 背景

A2 消费 A1 的只读投影，在会话区上方展示可任意顺序解决的配置缺口，并让仓库深链实际通向项目内配置。采用已确认的 URL 工作类型、三个固定提示和既有仓库命令；查询不产生领域写入，配置成功不触发委派或激活。

## 实施假设

工作类型只读取 URL 的 `workKind=repository|non_repository`；缺失、重复或非法值不查询、不推断。展示顺序按真实配置依赖图的最长路径降序：连接→仓库→上下文深度为 2，模型连接→启用模型、Agent 定义→Team 授权深度均为 1，同深度模型在 Agent 前。Runner 不进入缺口计数。

复用 `packages/db/src/agent-locks.ts` 的资源锁序 `agent_sessions→work_items→projects`，不另建逆序目标锁；Human 授权行锁与目标锁必须覆盖最终校验到提交，撤权先持锁则等待后拒绝，发布先持锁则撤权等待其提交。连接秘密用独立 HMAC 用途域和字段名区分，账本只存最终请求摘要；无法验证正文的旧脱敏键拒绝重放，不能靠自动换键规避。旧无筛选仓库请求保留权限、分页信封、排序和空过滤绑定；新 Human 筛选在 SQL 分页前执行且绑定游标，Agent 不获得新读取范围。
