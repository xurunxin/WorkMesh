## 建议的新增范围

现有 Agent、Delegation、Session、Connection、Runner Attempt 和系统秘密存储继续承担各自责任。TA02 建议新增机器身份及实例代次、带时间的能力观测、持久机器 slot、固定机器调度和独立用户级守护进程。机器在线、探测成功和持有 slot 均不授予业务权限。

等待审批仍占 Agent 并发额度，这是 ADR0046 的现行规则。机器物理 slot 是否在公开等待结算后释放，需要单独选择。推荐复用已经结算等待、自动续 Turn 的机制，再重新 admission；不能释放 Agent 容量或恢复旧 Attempt。

优先研究 Linux amd64 和 Windows x64 的守护进程，具体支持矩阵待裁定。Windows 后台验收保留。#20 已有 Linux arm64 发行与 macOS 安全回归保持；本轮不新增 ARM 执行，也不把连接器平台能力等同守护进程支持。

#33 的 API139／MCP139 仍未闭合，[PR229](https://github.com/xurunxin/WorkMesh/pull/229) 未合入。本方案可以独立审查；涉及其部署候选的未来联合验收须等准确依赖满足。任何有限负样本、临时包装和旧 CI 都不能替代该门禁。
