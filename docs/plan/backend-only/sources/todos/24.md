## 完整任务正文

## 目标

一个 Team 可指定**一个**总管：它是**既有的** agent，通过组合现有构件来协调，
**不因被指定而获得任何能力**，且默认不能对外产生不可逆后果。

## 交付物

- `chief_appointments` 表：`(workspaceId, teamId, agentId, status, revision,
  appointedByHumanActorId, appointedAt, endedAt)`，含 workspace/Team/agent/Human 的一致性约束，
  以及 domain event 与 outbox 行
- `(teamId) WHERE status = 'active'` 的**部分唯一索引**——「每 Team 至多一个」是数据库不变量
- 任命 / 换届 / 结束三个 Human 命令（带 revision 与幂等键）；换届在**同一事务**内结束旧代次并建立新代次
- **总管委派 = 该 agent 现有授权 ∩ 协调默认集**

## 能力分组（`capabilitySchema` 共 17 项，必须完整互斥穷尽）

| 分类 | 能力 |
| --- | --- |
| 协调默认集 | `work:read` `work:write` `comment:write` `message:write` `plan:write` `agent:delegate` |
| 须另批 | `repo:read` `artifact:write` `repo:write_branch` `repo:open_pr` `repo:merge` `ci:run` `deploy:staging` `deploy:production` `secrets:use` `automation:manage` `admin:*` |

## 约束

- **任命既不扩权也不缩权**：agent 原有委派一个字节不动。会话权限来自
  `agent_sessions.delegationId`，所以「默认排除」是靠**总管专用委派的能力交集**实现的，不是靠约定
- 显式放宽是**独立的有审计的人工作为**，任命本身永远不扩权
- `repo:read` 默认排除的**后果**：默认总管**读不了源码**，因此不能直接判断代码质量。要就单独批
- `artifact:write` 默认排除的**后果**：默认总管**不能发布 Artifact 或自己的 `review_result`**，只能引用他人的
- 唯一索引约束的是**身份**，**不约束推理串行**：`maxConcurrency` 与多会话模型仍允许该 agent 并发
- 旧代次会话保留审计归因，但**失去产生新分派效果的资格**

## 测试清单

- [ ] conformance 对 `capabilitySchema` 做全量分区，**漏一项即失败**
- [ ] 任命一个已持 `repo:merge` 的 agent 后：其普通会话权限不变，总管会话不含 `repo:merge`
- [ ] 显式放宽产生独立审计事实，且不改动 agent 原有委派
- [ ] 换届原子性；并发任命只有一个成功
- [ ] 结束任命后旧会话无法再产生分派效果
