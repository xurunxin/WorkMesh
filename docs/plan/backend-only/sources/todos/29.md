## 完整任务正文

## 目标

agent 必须能**找到**总管并**向它汇报**；且工具加到 API **不等于** agent 能用。

## 证据

- ADR 0042 L16-22：exact Session 的 derived capability manifest 由 route-policy / feature / MCP bindings 生成
- ADR 0067 L13-19：平台工具只展示支持且 eligible 的操作，服务端逐次授权
- `apps/mcp/src/index.ts:307` 已有 `request_approval`，`apps/agent-runner/src/workmesh-tools.ts:268` 已映射它
  → **不需要**新增同义的「请求人类批准」工具

## 交付物

- `get_chief` —— **纯 Query，无副作用**：解析当前 Team 的 active 总管、appointmentId / revision、房间 id。
  没有它，agent 连总管的 id 都拿不到（房间 id 不可从它持有的任何东西推导）
- `report_to_chief` —— **Command**：投递到该房间、地址给总管 actor、落回执、返回引用

## 路由失败的原子契约

| 情形 | `get_chief` | `report_to_chief` |
| --- | --- | --- |
| 有权限但无 active 总管 | 返回 `chief: null`，不建房不任命 | `CHIEF_NOT_APPOINTED`，不发消息、不静默升级 |
| 目标 Team 无权 | 统一 `NOT_FOUND`，不泄露存在性 | 同样 `NOT_FOUND`，不转发 |
| 两次调用之间任命已变 | 返回当前 appointmentId / revision / roomId | 请求带预期值，事务内加锁重验；陈旧返回 `CHIEF_APPOINTMENT_CHANGED` |
| 已提交后同 key 重放 | 不适用 | 返回原 message / recipient，不向新总管再发；异体按幂等冲突拒绝 |

## 完整交付链（只加 API 工具不算交付完成）

REST → contracts / SDK → route-policy 与 feature registry → MCP bindings →
derived capability manifest（ADR 0042）→ 工具适配（ADR 0067）→ conformance

## 约束

- Lite 类：总管推理必须由**外部 Runner** 执行，控制面只做准入与投递
- 「无专属常驻模型进程」≠ 无运行依赖；复用既有受限调度与补偿轮询
- 无 Redis 档位下消费与授权契约**不变**，支持度列为**兼容待验收**，不假定 0072 已实现
- 工作台在**无任命或功能关闭**时必须显示明确不可用态；布局不得暗示「总管可用」
