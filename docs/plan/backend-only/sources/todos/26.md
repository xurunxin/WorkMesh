## 完整任务正文

## 目标

让总管能被唤醒，但**不把定时器伪装成人类指令**，也不绕过既有的身份与预算机制。

## 证据

- 现有 `prompt()` 命令**只接受 Human**（`apps/api/src/agent/commands.ts:2843-2853`），
  接不住 agent 汇报或服务计时器
- `automation_rule_versions.trigger` 确实支持 `{type:'schedule',cron,timezone:'UTC'}`（有界五字段 cron，
  `packages/contracts/src/index.ts:2091-2104`；worker `apps/worker/src/automation.ts:490-528` 会调度 occurrence），
  但其 `start_session` / `delegate_agent` 路径**绑定 Work Item**
- ADR 0024 L13-15 的 loop admission 可以创建**无 Work Item** 的会话，并带预算与 overlap
- 跨 Work Item 分派要求 **coordination** Session + 有效连接 +
  **principal 等于目标 Work Item 的 Responsible Human**（`agent/commands.ts:826-886`）
- `requestApproval()` 读取当前会话的 Work Item（L2934-2944）

## 交付物

显式 activation 命令，三源统一映射，记录真实 source kind / id、发起 actor（若有）、
执行 service actor、任命 revision、规则版本、resulting sessionId。
复用 ADR 0023 / 0024 的 occurrence、admission、budget reservation、fencing 与恢复。

## 约束

- **计时器不得伪装成人类指令**
- 团队有多个 Responsible Human：**保留 principal 等式**。不匹配的动作退回该 Work Item 的负责人，
  「Team 总管」身份**不赋予任何 principal 代行权**
- 按 source event / message / occurrence **去重**；**排除总管自身事件**进入自己的唤醒集（防事件自环）
- 合并唤醒，并限制激活速率、队列积压、每 Team / 时间窗累计预算；明确定时补偿与 DLQ
- **单会话预算挡不住自激活** → 累计预算必须跨激活强制
- **Stop 当前会话后不得由同一输入重建会话**；提供人可用的全局暂停 / 结束任命开关，启动前再次验证

## 测试清单

- [ ] 同源重复去重；两个消费者竞争
- [ ] admission / session / prompt / event / outbox 各边界崩溃
- [ ] **无 runner**（对应 ADR 0074 的 `unknown`）
- [ ] 主负责人不匹配时退回
- [ ] 旧任命 / 被撤权 / Stopped
- [ ] **事件自环**（总管自己的事件不得唤醒自己）
- [ ] 累计预算耗尽

## DoD

上述断言全绿 + 三种激活源在记录里可区分 + 预算与 Stop 不可被自激活绕过。
