## 目标

让总管的跨会话连续性成立。**这一条不是待接线，是待建。**

## 证据（为什么「构件都在」不成立）

- ADR 0033 L19-21 明确 durable event cursor、opaque collection cursor、Session sequence **分属不同域**；
  L60-69 明确 retention floor、`CURSOR_EXPIRED`、SDK 自持 checkpoint、MCP `list_events` 无状态
- `apps/api/src/realtime/event-reader.ts:125-140` 读的是**经实时授权的事件页**，不返回 Team 状态差分
- `schema.ts:312-314,399-400` 的 snapshots / deltas **没有**总管消费 checkpoint
- `guidance.ts:229-244` materialize 的是 scope / work item / guidance pins，**不是按 domain cursor 的全 Team CDC**
- `collaboration/routes.ts:1436-1478` 的 delta 由调用方指定 source/hash，**不是自动计算**

## 交付物

- checkpoint 键至少含 workspace / Team / **任命代次** / 消费者版本
- server cursor 为**十进制字符串**，且**不与列表游标混用**
- 冻结可重建 baseline 的版本与水位；**快照—事件衔接是定义好的协议**，不是两个 GET 拼起来，
  因此 baseline 构建期间的并发写入既不丢也不重复
- 事件按 id **幂等合并**成 changed-resource 集，并处理**删除与撤权**；payload 不足时按当前授权重读资源
- 「已处理至 C」与该批已提交的提案 / 激活结果**原子关联**；分派效果由独立 logical dispatch 记录与幂等身份去重；委派 id/revision 仅为授权来源
- 新会话输入 = **版本化、受限大小的派生摘要 + 增量**，来源可追溯，**不成为业务权威**
- `CURSOR_EXPIRED` / 消费者版本变更 / 授权**扩大** → 有界全量重建；授权**收缩** → **先移除**不可见数据

## 约束

> **增量读是带量化预算的容量验收要求，不是正确性前提。** 首次、游标过期、授权变化与修复都允许
