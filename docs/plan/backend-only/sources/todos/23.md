## 完整任务正文

## 目标

**A Team room is refused by the database today.** 这不是「加一个枚举值」那么小的事：
`packages/db/migrations/v1/0001_v1_baseline.sql:599-614` 的 `CHECK` 只有 work_item / project / session
三个分支，而 `enforce_room_subject()` 把任何非 work_item/project 的值走进 session 分支，
找不到对应 agent_sessions 就抛 `WORK_ROOM_SUBJECT_NOT_FOUND`。所以插入 Team 房间会先被触发器挡住。

## 证据

- `packages/db/src/schema.ts:27` — `room_subject_kind` 确为三值
- `packages/db/src/schema.ts:349-351` — `work_room_channels` **没有归档字段**
- ADR 0078 初稿曾写「沿用现成的创建与归档命令」，**该说法已被审查推翻**

## 交付物

1. **迁移 entry 1**：只 `ALTER TYPE room_subject_kind ADD VALUE 'team'`，**本 entry 内不使用该新值**。
   PostgreSQL 允许事务内 ADD VALUE，但新值在事务提交前不可用。
2. **迁移 entry 2**：替换 `CHECK` 与 `enforce_room_subject()`，新增 `team` 分支——
   同 workspace 内解析 Team，要求 `subject_id = team_id`，且 `workItemId` / `projectId` / `sessionId` 均为空。
   三种既有 subject 分支与其唯一键**原样保留**。
3. contracts / OpenAPI / subject 类型 / room 发现 / 消息写入 / recipient 校验 / inbox scope /
   event resources 与 audience / context message 引用全部支持 Team subject。
4. 任命事务确保常驻房间存在，沿用 `(workspace, subjectKind, subjectId)` 唯一性。
   **结束任命不删除房间与历史**。本 ADR 不定义归档（今天没有归档命令，将来要归档需自带生命周期、授权与迁移）。

## 约束

- 旧 baseline / legacy 迁移与其 checksum **一字不动**；不为加枚举值重生成已发布 baseline
- 迁移文件内**不写 `BEGIN` / `COMMIT`**（runner 托管事务）
- **房间本身的可见性**与**房内 exact-recipient 消息的可见性分开检查**；任命不授予任何 scope
- 「能发现这个房间」不等于「能读房里所有内容」
