## owner 口径（2026-10-07，覆盖本条初稿）

> **总管在委派范围内自主分派；人通过「修订」介入，不是逐项批准。**
> 任务交给总管即等于按目标放权。
>
> 初稿写的「每一次分派都需要一次人类决定」**已撤回**——那会让总管退化成事事请示的
> 下属，等于取消了协调者。外部审查 H3 曾推荐该方案，**该建议被否决**。

## 目标

把授权单位从「逐次决定」改成「一次委派」。委派是常设、有界、可撤销的授权，
与 ADR 0062 的自主策略**并行**，因此**本条不收窄 0062**。

审查 B1 仍然成立并保留：**自由文本消息不构成授权**。

## 交付物

**总管委派**，绑定 workspace / Team / `appointmentId` + revision / principal /
所覆盖的目标或 scope / 能力 / 资源范围 / 预算 / 有效期 / 最大使用次数。

每一条分派**引用**该委派的 id + revision —— 因此可归因、可审计、**可撤销**，
而人不需要在每次分派时介入。执行命令在状态变更事务内**校验**委派仍然有效。

## 约束

- **自由文本仍然不是授权**：房间中**显式确认**必要字段的操作可创建或扩展委派；
  自由文本须先成为结构化提案，被确认后才成为委派
- 执行命令保留**真实 agent 作者**并引用委派，**绝不写成 Human 作者**
- **总管不得自行扩权**；扩权是 Human 命令
- 与 ADR 0062 **并行**：两者都是常设、有界、可撤销的授权，互不冲突，
  也都不允许 agent 自行扩权
- 人的杠杆是**修订**不是逐项批准：改委派范围 / 停会话或工作项 / 改工作项本身 /
  撤换任命 / 两个执行关口（确认方案、审核改动）
- 五个执行入口 `delegate_work_item` / `claim_work_item` / `create_child_session` /
  retry / automation **共用同一 guard**——只查 `report_to_chief` 或某个 MCP 包装层
  会被创建、child、claim、automation 绕过
- 执行会话**持久标记**为携带总管执行上下文，使越过任命期限或委派被撤的旧会话
  无法静默降级为普通 agent
- 不得把任意 `decisions.status='final'` 或 `room_message.intent='decide'` 当作委派

## 测试清单

- [ ] 普通人类自由文本**不产生授权**（可作为输入，但无法凭它分派）
- [ ] **委派范围内的分派无需逐次批准且成功** ← 本条的核心行为
- [ ] 委派范围外的分派被拒
- [ ] 缩小范围 / 过期 / 撤销后**立即**拒绝

- [ ] 校验与 session / event / outbox 任一点失败共同回滚
- [ ] Stop / 撤权 / 换届后旧会话不得再分派
- [ ] 五个执行入口行为一致（共享 guard，不是只查一处）
