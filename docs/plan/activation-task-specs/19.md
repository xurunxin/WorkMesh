## 四个 blocking / high 的要点

**F01（blocking）｜连接器验收自相矛盾，且弱于既有 ADR 0046。**
持久化「精确请求 body」必然含 `wmp_` 配对码（它本身是秘密），与「恢复文件不含秘密」冲突；
而原顺序允许指纹+Skill 两项通过就替换配置，ADR 0046 要求必须在原始 Skill 校验
**及** `initialize → verify_connection → get_workmesh_context` 身份比对**之后**才写正式配置。
→ 合并 `#5`+`#6` 为一个可执行纵向任务。**并撤回**「撤销后不返 secret」的假定：
既有重放命中时直接解密返回、不重跑撤销检查，正确测试是「身份验证拒绝已撤销/过期凭据且绝不写入新配置」。
另：Windows 不能仅凭 mode=0600 宣称保护成立，需定义并**验证**当前用户专用 ACL。

**F02（blocking）｜D5 要求跨卡片原子提交，却承诺不改端点与领域。**
现有单项移动是逐条 PATCH、逐条独立事务提交，**不存在批量原子移动契约**。
→ 拆为 D5a（状态化主动作与菜单）与 D5b（拖拽/多选/草稿引用）；
批量部分改为**逐项结果 + 部分失败恢复**。坚持全批次原子需独立 ADR 定义批次键、锁顺序与回滚。
另：「复制链接」「拖卡入输入框」是纯本地交互，**不发领域 mutation**，不应要求幂等键与 revision。

**F06（high）｜单暖色的状态词汇不属于同一个模型，其中一项在本仓库并不存在。**
`awaiting_review` **不存在**：工作项类别是 `backlog/planned/started/completed/canceled`；
Agent Session 有 `awaiting_approval` 但**没有** `awaiting_review`；`view-model.ts` 把两者**分开保留**。
→ attention 色必须由**已授权的 Human Attention 投影**判定「当前需要人响应」来驱动，
**不以状态名前缀推断**，也不把会话状态回写到工作流列。**遍历虚构枚举的全绿不构成验收。**

**F08（high）｜输入可达性：build 读不到任务引用的文件 —— 见 `#18 G1`。**
每次 build 从 base 分支独立检出到 `C:\Users\xurx\.tds\workspaces`，remote shell 关闭、无额外 MCP 连接。
四份 ADR 位于 `docs/adr/` 而该目录 `.gitignore` 内容是 `*`，且目前都只是**未跟踪文件**——
**在它们进入 base 之前，任何依赖这些输入的构建都无法读到自己的任务书。**
