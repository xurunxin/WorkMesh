# WorkMesh 工作树持续收尾规则

用户最新原话：『目前整体工作树占用了42G以上的空间，目前在执行的任务只有1个，正常应该不会有这么多文件残留，注意设定好清理机制，避免磁盘占用不断膨胀』。

本文件落实本卡已授权的收尾偏好。可复用实现是 [usage-inventory.py](usage-inventory.py) 的**只读盘点**和 [cleanup-rules.json](cleanup-rules.json) 的安全规则；本卡接续的实际回收在 [continuation/report.md](continuation/report.md)。没有注册定时任务，没有修改 tds/平台守护进程，也没有声称 daemon 已自动回收。

## 触发与最小保留

1. **开工前盘点。** 在本项目构建开始时运行以下命令，记录普通文件逻辑长度、工作树数量、前十个大目录和组成变化。不给未归属目录递归扫描，不跟随链接。空间异常先说明组成，禁止为了达到某个占用数而解除保护。

   ```powershell
   $env:PYTHONUTF8='1'
   python -B docs/reviews/cleanup/2026-10-11-worktrees/usage-inventory.py --phase opening
   ```

2. **合入后纳入待回收台账。** 记录机器、绝对路径、todo、branch、完成 HEAD、PR、远端 main 原返回及时间。合入不是删除条件本身。处理该项目下一次收尾时先核近期候选，不等它们成为大量长期残留。本卡的 `continuation/mapping-54..57.json.gz` 和执行回执是实际范例；后续应新建日期目录，不能重写这批回执。
3. **必要原件最小保留。** 优先复用主线可达的 Git blob、既有源码/runtime ZIP 和原输出成员。逐 path 分列 Git 与 Windows 原字节，注明 CRLF/BOM/二进制差异。缺少的必要本任务材料先脱敏保全、按内容哈希复用成员，再提交来源和预检。依赖/构建缓存记录真实锁版本、工具版本、源码和构建脚本，只承诺可重建的功能性输出；不把缓存当验收原件，也不承诺重建字节等同。运行时包只保留一份内容相同的原包，避免每个候选重复归档。

## 实时安全门与幂等回执

每个候选在删除紧邻前独立查询 `refs/heads/main`，用返回的 immutable SHA 证明完成 HEAD 和必要历史成果可达；不用共享 `FETCH_HEAD`、陈旧 `origin/main`、Done 或 PR 标签替代。刷新活动 todo/当前对话、可见进程的命令行和可执行路径，以及明确的恢复输入。检查 dirty/untracked/ignored、嵌套仓库、所有链接本体与解析目标、原字节哈希、独占读取和精确绝对路径边界。无法取得充分证明的目录留存，并写清缺少哪一个输入。

先提交逐候选预检和保全来源，再执行正式 `git worktree remove`。无登记独立 clone 需另有明确归属和全部子目标安全证明。对于本卡同版 Git 实测会保留的 junction，预检须**事先**声明收尾序列：只有 Git 成功、残留全为原已核 junction/普通空目录时，才原生 PowerShell 非递归移除链接本体和空目录；不递归链接目标。出现失败、未声明残留或任何自动审批拒绝，停止原目标，保留实际输入/输出/exit，不 Force、不改属性/ACL、不拆批或换工具绕过。该序列不能套用到历史被拒目标。

每次实际调用记录 `machine + absolute path + completed HEAD`、时间、输入、stdout/stderr、退出码、逐目标结果、操作前后卷空间。目标已不存在且有成功回执时只读核回执，不再次发删除；已有停止/拒绝回执时不自动重试。仅有缺失路径而没有旧回执，记录历史缺口，不补造成功。事后核目录不存在、登记健康、活动/保护路径存在性。逻辑长度与卷级可用空间变化分列，可归因物理净释放无法证明时写“未知”。本卡 #53 的原回执不重跑、不改写。

## 永久继承的保护边界

精确原路径和来源来自 `protected-paths.json`、`historical-sources.json` 所绑定的真正 main 历史报告，不用文件类型名称扩大或缩小它们。G1/D0/C3 拒绝目标及父目录，旧 38 node_modules、36 `.turbo`、2 typecache，RAW/原 trace/未映射验收物、恢复输入仍保护。新近工作树只有经过精确交叉核对不属于这些路径，才进入新候选。

本次 #58 全工作区和 M5 服务、#5 待审及历史恢复、#21 首面 checkpoint、当前清理构建、主仓库、其它项目、平台缓存、用户目录、共享 store/镜像/业务数据都不成为清理目标。不停止他人服务，不扩大 Docker 清理，不删除远端分支、标签或审计记录。

## 平台自动化的具体后续方案

若希望今后无需人工启动，建议**合入事件驱动的待回收队列 + 开工前只读盘点**，而非设置固定时间批量删除。平台在 PR 实际合入后写入机器/路径/HEAD 候选，构建开始时生成占用快照；独立清理执行器消费队列，按上述实时安全门、先行提交和拒绝终止规则执行，并用三元组幂等键持久保存回执。保护登记必须优先于 Done，活动/恢复引用不明时只留存，不自行过期解除。

这需要平台合入事件、任务/恢复登记和机器执行器代码支持，属于本项目工作树清理之外的实施分叉；本卡没有改平台代码、授权规则或守护进程，也没有擅设触发频率。当前交付提供可复用的盘点、规则和实际执行样例。建议后续平台实现以此规则为合同，另行明确实现范围和授权后接入；不要把本文件描述成已运行的自动服务。
