建议提交给 Chief 的具体矩阵：Linux amd64/arm64 两架构，带版本自包含可执行产物（含仓库 `.node-version` 对应运行时）、清单和 SHA-256，目标设备无源码、无 pnpm workspace 和宿主 Node 前置。在干净目标环境安装后运行相同完整连接校验，秘密存储适配也要实测。这是保持原二进制/无源码要求的建议，矩阵尚未获批；不根据 Proposed Lite 的内存估算发明最低硬件验收数字。Windows pending ACL 仍归 #5，不能用发布矩阵删掉它。

需要裁定的是实际目标系统/架构和设备环境。仅发 JS 包并要求宿主 Node 是另一个具体选项，但会改变原二进制/无额外运行时前置的验收口径，不能由本轮默认采用；若实际设备已有 Node 且用户选择该方式，明确修订对应要求再执行。#20 阶段一提交安装样例、产物清单、OS/架构/运行时与秘密存储条件，Chief 对照已有设备需求落实例行选择，仅真实新增目标/要求分歧交用户；之后冻结构建计划，封装工具由执行者在该计划内决定。B4 文档归 #20：安装、客户端配置、完整验证、错误恢复、版本/卸载说明；不再是待定悬空节点。外部注册表/Release 发布与新凭证仍另行批准。

## C2：企业微信出站协议核实

建议采用群机器人 Webhook，仅发送通用低敏提醒与登录网页深链，不发送工作标题、正文、人员信息或审批按钮，不引入 OAuth、身份桥接或回调。目标秘密引用归 C1；转发后网页仍以当前登录 Human 授权。必须确认目标企业允许使用群机器人且符合通知受众边界，不能把群成员当 WorkMesh Human。
