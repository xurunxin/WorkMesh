# WorkMesh v1.0.0

WorkMesh v1.0.0 is the first Stable Core release for self-hosted human and
coding-Agent collaboration. A release candidate is accepted only after the
exact tagged commit reproduces required CI, migration, disaster-recovery,
authorization, Inbox, browser, conformance, production-image, and security
gates. The attached machine-readable manifest binds the source commit,
dependency lock, schema migration manifest, feature registry, four image
digests, SBOM attestations, and build provenance.

## Supported deployment boundary

- PostgreSQL 16, Redis 7, and S3-compatible object storage with Object Lock;
- production API, Worker, MCP, and Web images pinned by digest;
- REST 1.0, Agent Protocol 1.0, Client Profile 1.0, MCP 1.0.0, and schema
  baseline 1;
- Beta and Experimental flags default disabled and are outside the Stable
  compatibility promise.

The Web image records its compiled public API URL in
`io.workmesh.web.api-url`. Operators must select the candidate whose recorded
URL matches their deployment or build a separately identified Web artifact;
changing this input is a rebuild and therefore requires a new RC.

## Known limitations

- restore uses a maintenance-window logical backup and is not point-in-time
  recovery;
- A2A 0.3 remains Experimental and disabled by default;
- notification schedules defer individual deliveries rather than producing a
  coalesced digest;
- the scheduler supports only the documented bounded five-field UTC grammar;
- multi-runtime reservation has no supported execution implementation;
- GA supports the single architecture recorded by each candidate image
  manifest; additional architectures require a new candidate and full gates.

## Unsupported upgrade paths

Only complete immutable pre-v1 ledgers ending at `0002`, `0006`, `0007`,
`0014`, or `0021` are supported. Unknown, partial, non-contiguous, or
checksum-drifted ledgers fail closed and require operator recovery. Direct
database edits, downgrade migrations, cross-major wire-contract breaks, and
restores into a non-empty target are unsupported.

## Promotion

The `v1.0.0` workflow verifies the candidate manifest and Sigstore evidence,
retags the same four immutable image digests, and refuses any build command.
Digest inequality blocks GA publication.
