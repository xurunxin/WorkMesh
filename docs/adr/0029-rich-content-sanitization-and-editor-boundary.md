# Rich-content sanitization and editor boundary

Status

Proposed, revision 2, for the repaired GEN-9 contract Gate. Implementation remains blocked until an independent Gate accepts the machine contract. No editor dependency is selected in this slice.

Context

WorkMesh already stores Work Item descriptions and comments as bounded text and exposes canonical comment, mention, artifact-upload, checksum, provenance, revision, CSRF, and idempotency contracts. Kaneo uses Tiptap-based editors, but its editor extensions, stores, upload behavior, router, and backend authority cannot be copied into WorkMesh. The existing frontend architecture explicitly deferred Tiptap, DOMPurify, and Mermaid until M3 decided the content model, paste and upload behavior, SSR, sanitizer ownership, license, and bundle budget.

Decision

WorkMesh will treat Markdown/plain text as the durable source format for GEN-9. The first implementation uses a native textarea with a small Markdown toolbar. Paste is normalized to plain text, native textarea history owns undo/redo, and the textarea value is the exact command body. The server-rendered textarea may have client event handlers but does not depend on an editor-only DOM or a client-only serialization model. Editor state is never authority and is not persisted as raw HTML or editor JSON. Tiptap and its peers are deferred; a later graph version must freeze exact versions, extensions, serializer, paste, SSR, license, and bundle selectors before installation.

Rendering accepts only the durable Markdown/plain-text value. A deterministic local parser owned by `apps/web/features/rich-content/markdown.ts` emits paragraphs, level-two/three headings, ordered/unordered lists, blockquotes, fenced code, inline code, links, bold, italic, and strike as React elements. It never injects untrusted HTML with `dangerouslySetInnerHTML`; raw HTML and unsupported syntax render as literal text. Links accept only `https:`, `http:` and contract-approved relative WorkMesh routes; `javascript:`, `data:`, `vbscript:`, credential-bearing URLs, executable downloads and unknown schemes are rendered as inert text. External links use safe opener/referrer behavior.

DOMPurify is rejected for the initial GEN-9 renderer because no HTML sink is authorized. Its applicable dual license therefore does not enter the product or notices in this slice. A future HTML-preview feature must create a new Gate selecting the license, environment, configuration, sink, SSR behavior, counterexample suite, and dependency version. Mermaid is rejected for GEN-9 and remains a separate isolated-renderer decision.

Mentions are structured actor IDs carried beside text and are resolved only from server-authorized Human visibility. Display tokens never grant access. Comment create, reply, edit, resolve, reopen, and soft-delete are Human-session commands using the canonical endpoints with revision, CSRF, and stable idempotency; their projection includes the Human actor kind. Agent-authored collaboration content does not masquerade as a Human comment. It uses the Work Room message or plan-step-comment projection. The shared transport projection carries actor ID, display name, actor kind, optional exact Agent Session ID, optional exact plan-step ID, and creation time. A null plan-step ID means the content is not scoped to a plan step, not that provenance is unknown.

Drafts are non-authoritative local recovery records scoped by Workspace, Team, actor, resource, field, and base revision. They expire, expose discard/reconcile controls, never contain upload credentials, and never auto-submit after reload, reconnect, or revision conflict. A changed base revision requires Human reconciliation before a new command.

Artifacts continue through canonical upload intents. GEN-9 extends that module with a Human Attachment variant rather than impersonating an Agent Session. A Human request contains only Work Item, filename, MIME, size, and checksum; the server derives project and `workmesh-web` source provenance and persists null Agent Session, plan-step, repository, pull-request, and head-SHA fields. The existing Agent shape remains session/repository scoped. Request, finalize, cancel, status, list, and download re-authorize the current principal and Team scope; finalize and cancel also bind the exact requester or exact Agent Session. The worker verifies the same checksum/size/MIME tuple and publishes an immutable file Artifact with an explicit producer actor and optional session provenance. Upload MIME is limited to PNG, JPEG, WebP, GIF, PDF, plain text, Markdown, JSON, CSV, and ZIP. Only the four raster image types may render inline, and only from a current authorized short-lived download URL; SVG, HTML, PDF, text, JSON, CSV, ZIP, metadata URIs, data URLs, and blob URLs are never embedded. Status and list projections redact storage keys, claims, credentials, signed upload URLs, and internal error text. The client may show progress, retry, and cancel for a bounded intent, but checksum, size, MIME, storage key, expiry, producer, work-item provenance, and finalization remain server facts.

Alternatives

- Persist Tiptap JSON or HTML as the primary model: rejected because it couples durable domain content to editor extensions and expands the unsafe rendering surface.
- Adopt DOMPurify immediately: rejected because the initial implementation has no authorized HTML sink; adding a sanitizer would create dependency and licensing cost without defining a safe content model.
- Copy Kaneo editor/upload stores: rejected because they would introduce a second authority and bypass WorkMesh revision, idempotency, upload, and provenance contracts.
- Tiptap in GEN-9: deferred because the initial slice does not need an editor runtime and the previous contract did not close exact peers, serialization, paste, or SSR selectors.
- Reuse Agent upload credentials for Humans: rejected because it would falsify actor/session provenance and weaken capability boundaries.
- Store Human files outside the Artifact model: rejected because it would create a second upload, checksum, authorization, and lifecycle authority.

Consequences

The editor is intentionally simple and replaceable. Some pasted formatting is lost. HTML and diagrams are not rendered in GEN-9. The full-stack candidate adds a forward-only migration that makes Artifact session/repository provenance nullable for Human Attachments, adds the verified Artifact ID to upload intents, and adds a canceled status. Deferred validation triggers join the requester/producer Actor kind across upload intents, Artifacts, and Artifact links, enforce mutually exclusive Human and Agent provenance, and require link session provenance to match its Artifact after existing rows are validated; application checks are defense in depth, not the only invariant. Existing Agent rows remain valid. Cancel commits the terminal state/event first and performs object deletion as best-effort cleanup; cleanup failure is observable but never reopens upload authority. Tests must include executable dangerous-HTML/URL vectors, mention scope, actor-kind separation, draft revision convergence, duplicate idempotency, stale revision, offline/reconnect, Human and Agent upload authorization, cancel/finalize replay, redacted projections, MIME allowlist/preview policy, checksum/MIME/expiry/restart failures, and responsive keyboard journeys. Bundle increases are bounded by the v29 TaskGraph.

Migration

Existing descriptions and comments remain valid Markdown/plain text. The immutable numbered pre-v1 migration inventory remains unchanged through 0035. Production v1 migration 0006 is the sole executable upgrade and relaxes provenance nullability for new Human Attachments, adds `artifact_upload_intents.artifact_id`, adds the canceled status, and enforces mutually exclusive Human/Agent upload provenance. It does not rewrite existing rows. Candidate source begins as the complete exact active-v28 monorepo and overlays only the current domain-contract document before implementation; mixing the older control-root server snapshot with the active-v28 dependency graph is forbidden. No editor dependency or lockfile change is permitted. Activation is full-stack and requires an independently verified migration/API/worker/Web contract plus an exact Human approval; application rollback must remain compatible with migrated rows.

Spec changes

TaskGraph v7 may change `OPENAPI.yaml`, shared contracts, the artifact-upload API/worker module, consolidated schema, migration v1/0006, its checksum manifest and inventory test exactly as described above. It may also type the Work Room content-attribution projection and make Work Item comments explicitly Human-authored. No provider, MCP, Connection, credential, delegation, lease, approval, or unrelated delivery-control behavior may change. Security scanning remains excluded by Human direction; functional content-safety and authorization tests do not constitute security approval.
