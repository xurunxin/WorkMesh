# Pi Runner WorkMesh operation matrix

Source: ADR 0067, W11, and the live `GET /api/v1/agent-capabilities` manifest. The matrix describes the Runner's available tools as of 2026-09-25. A tool appears only when the manifest marks its operation supported and eligible; every call is checked again by the API. An absent tool never implies that a similar request is allowed through another channel.

| Operation family | Pi tool / status | Authority and recovery |
| --- | --- | --- |
| Session context | `workmesh_session_context` / available | Exact Session token; bounded read. |
| Current Session revision | `workmesh_get_session` / available when eligible | Exact Session ID fixed by the Runner; read immediately before plan publication. |
| Project discovery/detail and ordinary writes | `workmesh_list_projects`, `workmesh_get_project`, `workmesh_create_project`, `workmesh_update_project` / available when eligible | Live scope; creation/edit requires Project management authority. Update requires If-Match. |
| Issue discovery/detail and ordinary writes | `workmesh_list_work_items`, `workmesh_get_work_item`, `workmesh_create_work_item`, `workmesh_update_work_item`, `workmesh_create_work_item_relation` / available when eligible | Live scope and appropriate `work:read` / `work:write`; Issue update requires If-Match. Responsible Human remains a Human. |
| Ordinary documents | `workmesh_list_documents`, `workmesh_get_document`, `workmesh_create_document`, `workmesh_update_document` / available | `work:read` or `work:write`, exact owner; update requires If-Match, base revision ID and content hash. Stable tool-call idempotency key on writes. |
| Evidence artifact | `workmesh_publish_artifact` / available with `artifact:write` | Exact Session bound by the Runner; URI and checksum validated by the shared contract and server. |
| Approval request | `workmesh_request_approval` / available when eligible | Exact Session bound by the Runner; sanitized payload, digest, risk, and expiry required. An Agent cannot decide its own request. |
| Coordination lease | `workmesh_list_leases`, `workmesh_acquire_lease`, `workmesh_release_lease` / available when eligible | Exact Session bound by the Runner; release requires the lease version in If-Match. Resource scope and lease policy are checked again by the API. A lease grants no authority. |
| Handoff offer | `workmesh_offer_handoff` / available when eligible | Exact source Session bound by the Runner; target acceptance and delegated authority remain server controlled. |
| Whole plan publication | `workmesh_publish_plan` / available with `plan:write` | Exact Session and If-Match; step IDs remain stable. The command's domain event is the initial audit fact, then the Runner appends a tool completion activity so the revision is not consumed before the command. |
| Session activity | `workmesh_append_activity` / available when eligible | Exact Session bound by the Runner; one visible team activity with tool-call and attempt IDs. No separate audit activity is appended around the activity command itself. |
| Session completion | `workmesh_complete_session` / available with an executing Session and eligible capability | The model supplies a summary, evidence or an explicit no-artifact reason, and current Session revision. The Runner queues the intent and calls the completion API only after the public answer is durably settled. A failed completion leaves the Turn settled and adds a visible warning when Session writes remain allowed. Crash recovery between Turn settlement and completion is still pending W11. |
| Handoff acceptance | Human-only | `acceptHandoff` requires a Human session in OpenAPI; Pi can offer a handoff but cannot accept it. |
| Approval decision, Guidance publication, Team/Agent policy, credential administration, irreversible deletion | Human-only | No Pi tool. Human authentication and server approval policy remain required. |
| Unrestricted shell, filesystem write/edit, Pi extension discovery | Disabled | Runner starts Pi without built-in tools in an isolated scratch directory. |

Ordinary writes record sanitized tool activity before and after the command. Plan publication records the domain event first and then a completion activity, preserving the supplied Session revision. The activity has an operation ID, tool-call ID, attempt ID, and payload hash. The command result, domain event, and outbox are authoritative. A repeated tool-call ID in the same attempt reuses the same idempotency key. Session Stop, delegation revocation, stale revision, owner-scope mismatch, and approval/lease requirements are enforced by the API, including after tool discovery.

Docker acceptance: start the `agent` Compose profile with a registered Agent installation token and one shared, at least 32 character `WORKMESH_RUNNER_SERVICE_TOKEN` in both API and Runner containers. On the isolated 2026-09-25 stage, Pi used the China MiniMax `MiniMax-M3` connection to call `workmesh_session_context` then `workmesh_create_document`; the Turn settled and the normal Issue document was persisted. The model key is held by the API connection vault and was not passed into the Runner container.
